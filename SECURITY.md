# Security Policy

## Supported scope

Security reports are welcome for the current public GLab Enterprise website at
https://guang84.github.io/ and the source code in this repository. The current
default branch is the maintained source of truth.

## Reporting a vulnerability

Please do not disclose suspected vulnerabilities in public issues, discussions,
or social posts before GLab has had an opportunity to review them.

Send a report to **he.3.glab.verse@gmail.com** with the subject
**[Security Report] GLab Enterprise**. Include, where possible:

- The affected page, component, file, or commit.
- A concise description of the potential impact.
- Reproduction steps or a minimal proof of concept.
- Any relevant browser, operating-system, or tool versions.

Do not include real passwords, access tokens, personal records, or other
sensitive data in the report. Use GitHub's private vulnerability reporting
feature for this repository instead when it is enabled and suitable.

## Coordinated disclosure and safe testing

Please allow reasonable time for investigation and remediation before making
technical details public. GLab will review reports and coordinate next steps;
a fixed response or remediation time is not promised.

Limit testing to systems and data you own or are explicitly authorised to
assess. Do not perform denial-of-service testing, phishing or social
engineering, persistence, destructive actions, or attempts to access, modify,
or retain another person's data.

There is currently no published bug-bounty programme or promise of
compensation for vulnerability reports.
