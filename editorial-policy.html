Editorial policy and corrections

GLab is maintained by Guang as a personal publishing site. Its scope is project documentation, technical explanations and reflections on technology. The About page provides background and links to the public source profile.

What different pages mean

A project case study explains a project’s purpose and design. A guide describes a workflow. An essay presents an argument or perspective. A link to a repository lets readers inspect the source, but does not by itself establish that a feature is tested, secure or suitable for deployment. Treat a documented capability and a measured result as different kinds of evidence.

Sources and limits

Use linked source repositories and primary documentation to check implementation details. Software and dependencies change; compare the relevant revision before following instructions. Where a page does not specify a test environment, version or measured result, do not interpret its description as a benchmark or a guarantee.

Reporting a correction

Email guang.social.verse@gmail.com with the page URL, the statement you believe is incorrect, and a source or reproducible example. For technical errors, include the software version and expected versus observed behavior. Remove credentials and personal data before sending logs. Suggestions for clearer explanations and broken-link reports are also welcome.

Dates and changes

Publication and update dates provide context for an article. They should not be taken as proof that every dependency or external link has been checked on that date. For a repository’s current behavior, inspect its own history and documentation. If an important limitation is missing from a page, report that limitation through the same correction channel.

Advertising and external resources

GLab is configured to use Google AdSense on content pages. An advertisement is not a recommendation from Guang, and a link to an external project or service is not a promise about its availability or quality.
