Purpose

Learning wireless security by observing a controlled lab.

Network Analyzer packages common wireless-analysis tools behind a guided Bash workflow and a lightweight local web interface. The repository explicitly describes the project as educational and discourages unauthorized activity.

Public user guide ↗

Tooling

A Linux-oriented shell and browser workflow.

  • Checks for root privileges and supported Linux distributions
  • Detects Aircrack-ng utilities plus mdk3/mdk4
  • Uses Bash for the interactive analysis workflow
  • Serves the accompanying interface through a restricted Python HTTP server
  • Keeps example output and learning resources alongside the source

Scope

Capabilities belong inside an authorized environment.

The repository describes traffic observation, wireless discovery, handshake capture, client deauthentication, and password-auditing exercises. Those operations can interrupt networks and must be limited to isolated labs or networks with explicit written permission.

Use only hardware and networks you own or have explicit authorization to test.

Implementation

Transparent components that can be inspected before use.

The public repository includes the main Bash workflow, a Python static server, browser-side JavaScript, interface assets, process notes, and selected upstream source references. This makes the learning environment inspectable before privileged execution.

Architecture

Network Analyzer execution model

A privileged Bash workflow coordinates wireless utilities while a small Python server exposes local interface and learning assets in the browser.

  1. mybash.sh verifies root access, detects the Linux distribution, and checks for required Aircrack-ng and mdk utilities.
  2. The shell workflow presents guided network-analysis options and invokes installed command-line tools against a selected wireless interface.
  3. server.py uses Python's standard HTTP server on port 8000 and restricts translated paths to the current working directory.
  4. HTML, CSS, and browser-side JavaScript provide the local visual interface and supporting process information.
  5. Captured material and audit exercises must stay inside an isolated, authorized lab; the web interface does not remove the safety implications of privileged wireless operations.

Setup & usage

Prepare an authorized Network Analyzer lab

Review and preview the public interface first, then restrict any privileged wireless exercise to isolated hardware and a network you own or have written permission to test.

For: Learners preparing an isolated, explicitly authorized wireless-security lab.

Prerequisites

  • A Linux system you control
  • A compatible wireless adapter and access point you own or are authorized to test
  • Python 3
  • Trusted distribution packages for Aircrack-ng and mdk tooling

Procedure

  1. Create an isolated lab with a compatible Linux system, a dedicated wireless adapter, and an access point you own or are authorized to test.
  2. Clone the repository and inspect mybash.sh before granting it root privileges; review every external utility and operation it can invoke.
  3. Use python3 server.py to preview the local interface at http://0.0.0.0:8000 without beginning a wireless assessment.
  4. Install Aircrack-ng and mdk tooling from your distribution's trusted package repository and confirm the adapter supports the required lab mode.
  5. Run the Bash workflow only inside the authorized lab. Do not capture third-party traffic, disrupt client connections, or audit credentials without explicit permission.
  6. Remove captured material after the exercise and record the scope, authorization, date, device, and results.

Command reference

git clone https://github.com/Guang84/Network-Analyzer.git
cd Network-Analyzer
python3 server.py
# Review mybash.sh before any authorized lab-only execution

Verification

  • The local interface opens through the Python server
  • Required wireless utilities are detected from trusted package sources
  • The lab scope, devices, authorization, and time window are documented before privileged testing

Troubleshooting & boundaries

  • If the interface does not load, confirm the local server is running and port 8000 is available.
  • If wireless functions are unavailable, verify adapter support and the required Linux permissions before changing any network mode.
  • If a step could affect a third-party network or client, stop and re-check the authorization boundary.

Testing

Network Analyzer authorized-lab checklist

Safe static, interface, dependency, and lab-scope checks for a tool whose privileged wireless operations require explicit authorization.

  1. Run bash -n mybash.sh and python3 -m py_compile server.py before executing either component.
  2. Start server.py as an unprivileged user and confirm the interface loads locally while path traversal remains blocked.
  3. Review the supported-distribution detection and verify every required wireless utility comes from a trusted package source.
  4. Document the access point, adapter, channel, client devices, written authorization, and time window for the isolated lab.
  5. Confirm the workflow refuses non-root privileged operations and clearly displays the educational-use warning.
  6. After the exercise, stop monitor mode, restore network services, remove captures securely, and record outcomes without third-party identifiers.
