Overview

Operational visibility through a small, inspectable toolkit.

The project began as SSH-Infiltrator and is evolving into SSH Fleet Doctor. It joins a Bash-based control workflow with a Python command-line monitor for remote resource checks and administrative tasks.

Its public documentation describes health monitoring, logging, backups, reporting, multi-server work, and error handling.

Read the repository ↗

Capabilities

Connect, inspect, record, and respond.

  • Connect to authorized SSH hosts
  • Inspect CPU, memory, disk, and network statistics
  • Execute selected or custom administrative commands
  • Record actions for auditing and troubleshooting
  • Support scheduled tasks, file backup, and system reports

Architecture

Shell orchestration with a Paramiko-based Python path.

SETUP.sh creates a Python environment and installs Paramiko. SSH_Infiltrator.sh provides the interactive shell workflow, while python/SSH_Intruder.py accepts host and username arguments and prompts for a password when one is not supplied.

Safety

Administrative power requires explicit boundaries.

The tool can invoke disruptive remote operations. It should only be used on systems you own or are explicitly authorized to administer, beginning with a disposable test host. SSH keys and a restricted account are preferable to passing passwords on the command line.

Never point the toolkit at an unknown or production host until every enabled action has been reviewed.

Architecture

SSH Fleet Doctor component map

The repository combines an interactive Bash administration layer, a Python/Paramiko monitoring client, environment setup, logging, and release automation.

  1. SETUP.sh checks for Python and pip, creates a virtual environment, activates it, and installs Paramiko.
  2. SSH_Infiltrator.sh provides the historical interactive control workflow for connections, commands, monitoring, backups, scheduling, and reports.
  3. python/SSH_Intruder.py validates the supplied IP address, creates an SSH client, prompts for credentials when needed, and exposes resource-monitoring and custom-command functions.
  4. Local log files record tool actions for troubleshooting and audit review; sensitive credentials should never be committed to those files.
  5. The tool boundary is an explicitly authorized SSH host. A restricted remote user and SSH keys should be used for any environment beyond a disposable lab.

Setup & usage

Set up SSH Fleet Doctor safely

Prepare the Bash and Python tooling against a disposable or explicitly authorized SSH test host before considering operational use.

For: Administrators or learners testing SSH monitoring against a disposable or explicitly authorized host.

Prerequisites

  • Linux, macOS, or WSL
  • Python 3 and pip
  • An SSH client
  • A restricted account on a test host you are authorized to administer

Procedure

  1. Use Linux, macOS, or WSL with Python 3, pip, an SSH client, and a test host you are authorized to administer.
  2. Clone the current SSH-Fleet-Doctor repository and inspect SETUP.sh, SSH_Infiltrator.sh, and python/SSH_Intruder.py before executing them.
  3. Run SETUP.sh to create the venv and install Paramiko, then activate the generated environment.
  4. Start the Python monitor with the test host IP and restricted username. Omit the password argument so the tool prompts instead of exposing it in shell history.
  5. Begin with read-only resource monitoring; review logs and remote permissions before enabling administrative operations.
  6. Prefer SSH keys, host-key verification, a restricted remote account, and tested backups for any non-disposable system.

Command reference

git clone https://github.com/Guang84/SSH-Fleet-Doctor.git
cd SSH-Fleet-Doctor
chmod +x SETUP.sh SSH_Infiltrator.sh
./SETUP.sh
source venv/bin/activate
python3 python/SSH_Intruder.py -i <authorized-host-ip> -u <restricted-user>

Verification

  • The Python virtual environment activates and Paramiko imports successfully
  • Read-only CPU, memory, disk, and network checks work on the test host
  • Logs contain useful context without credentials or secrets

Troubleshooting & boundaries

  • For connection failures, verify host reachability, SSH service status, username, and host-key expectations.
  • For dependency failures, recreate the virtual environment and install from the project setup script.
  • For production-like hosts, use SSH keys and a restricted account rather than command-line passwords.

Testing

SSH Fleet Doctor preflight checks

Static and disposable-host checks for the public Bash and Python clients before any authorized operational trial.

  1. Run bash -n against SETUP.sh and SSH_Infiltrator.sh, and compile-check python/SSH_Intruder.py without connecting to a host.
  2. Create the virtual environment and confirm Paramiko imports successfully from the activated environment.
  3. Reject malformed IP input and confirm omitted passwords are requested interactively rather than written to shell history.
  4. Use a disposable SSH host to verify read-only CPU, memory, disk, and network monitoring before testing administrative actions.
  5. Confirm logs contain useful operational context without credentials or other secrets.
  6. Exercise timeout, refused connection, invalid credential, and lost-session paths; verify the client exits safely and explains the failure.
