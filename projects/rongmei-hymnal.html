Purpose

A digital home for songs carried by community memory.

Rongmei Hymnal gathers multiple songbooks without flattening their individual identity. Credits, sources, editorial notes, and rights information stay connected to each collection.

The interface is designed for worship, learning, community singing, and long-term digital access on phones, tablets, and computers.

Collection

Three collections, 1,271 searchable songs.

  • Buanthanhlu: 305 songs
  • Hymdaihlu: 930 songs imported from a legacy SQLite source
  • VBS Songs: 36 public-domain or traditional English selections
  • JSON metadata and schema files keep the library structure explicit

Experience

Built for focused reading and unreliable connectivity.

  • Search across all registered songbooks
  • Adjust the reading layout and use presentation mode
  • Save favourites, history, and reading preferences on the device
  • Install as a PWA and explicitly download the library for offline use
  • Refresh downloaded content when a newer collection version is detected

Architecture

Rongmei Hymnal architecture and data model

A static PWA architecture separates the application shell, book registry, per-book metadata, song data, local preferences, and explicit offline downloads.

  1. index.html, book.html, and hymn.html provide library, collection, and focused-reading views styled by css/main.css.
  2. data/songbooks/index.json registers each collection with its directory, metadata path, version, and song count.
  3. JSON schemas document expected song and metadata shapes; individual collections retain their own source, editorial, credit, and rights records.
  4. JavaScript modules divide application startup, data access, rendering, settings, local history/favourites, contact information, and offline storage responsibilities.
  5. The service worker caches the app shell; an explicit download workflow saves selected library data and reports storage progress and status.
  6. Version comparison refreshes downloaded content when the app reconnects and newer book metadata is available.

Setup & usage

Run, install, and use Rongmei Hymnal

Preview the static application locally, then install it from its HTTPS deployment and explicitly download songbook data for offline reading.

For: Readers, maintainers, and community users who want to run or install the static hymnal application.

Prerequisites

  • A modern browser
  • Python 3 or another static HTTP server for local preview
  • HTTPS deployment for installation and service-worker features

Procedure

  1. Clone the repository and start a static HTTP server from its root; opening files directly through file:// will not reproduce service-worker behavior.
  2. Open http://localhost:8000 and search or select a registered songbook to verify the library and reading views.
  3. For installation, open the HTTPS deployment in a supported browser and choose Install app or Add to Home Screen.
  4. Choose Download for offline inside the application, monitor progress and storage status, and wait for completion before disconnecting.
  5. Use the home-page controls to refresh or remove the downloaded library. Browser quota and persistence remain controlled by the operating system.
  6. Review the usage policy before redistributing lyrics, editions, arrangements, recordings, or cover art.

Command reference

git clone https://github.com/Guang84/RongmeiHymnal.git
cd RongmeiHymnal
python3 -m http.server 8000

Verification

  • Search and reading views work at phone and desktop widths
  • The app can be installed from the HTTPS deployment
  • Downloaded collections remain available after disconnecting and reopening the application

Troubleshooting & boundaries

  • Do not open the application through file:// when testing service-worker or offline behavior.
  • If installation is unavailable, confirm the deployment uses HTTPS and the browser supports PWA installation.
  • If offline data is missing, reconnect and complete the in-app download before disconnecting.

Testing

Rongmei Hymnal release checklist

A validation checklist derived from the repository's schemas, versioned book registry, offline workflow, reading interface, and content-rights boundary.

  1. Confirm each registered book directory, metadata file, version, and song count agrees with data/songbooks/index.json.
  2. Validate song and book records against schemas/songs.schema.json and schemas/book-metadata.schema.json.
  3. Test search, focused reading, font settings, favourites, history, and presentation mode on phone and desktop widths.
  4. Install from HTTPS, complete an offline download, disconnect the network, and reopen previously downloaded collections.
  5. Reconnect after increasing a book version and verify the application detects and refreshes changed library data.
  6. Review credits, source notes, editorial status, and rights metadata before publishing any new collection.
