Context

Software shaped by day-to-day rural broadband operations.

The platform grew from practical challenges in a newly established broadband franchise with limited infrastructure, operational support, and dedicated software. Manual customer, fault, planning, and documentation processes were brought into one web-based system.

Read the project documentation ↗

Platform

One operational workspace across service and infrastructure.

  • Customer information, requests, plans, notices, and public service delivery
  • Administrative records, complaints, reporting, configuration, and audit logs
  • Broadband latency, connectivity, and network-health monitoring
  • GPON/OLT and fiber-infrastructure documentation
  • Geo mapping, route measurement, topology visualization, and installation planning

Deployment

A stable public gateway to a local operational system.

The production Python application ran on a local office server connected to the operational broadband environment. GitHub Pages provided a permanent public gateway, while JSON configuration and status checks selected a dynamic tunnel or maintenance state.

Outcome

Completed, production-tested, and preserved as a portfolio system.

The documented production deployment is now retired. The public repository preserves the gateway, screenshots, demonstration material, architectural description, and workflow evidence while deliberately excluding customer data, credentials, internal topology, server configuration, and private production source.

Public documentation demonstrates the system without exposing production data or sensitive infrastructure details.

Architecture

Noney Broadband NMS system architecture

The documented system joined a GitHub Pages gateway, dynamic tunnel routing, a local Python application server, operational modules, and broadband-office infrastructure.

  1. GitHub Pages supplied a stable public entry point and static maintenance experience.
  2. redirect-config.json described prioritized endpoints, timeouts, retries, delays, and user-facing status messages for the gateway.
  3. A dynamic tunnel connected the public gateway to a locally hosted Python application when the production service was available.
  4. The application centralized customer services, administrative workflows, network monitoring, infrastructure documentation, reporting, and configuration.
  5. Geo mapping and NetVision modules represented fiber routes, splitters, endpoints, cable lengths, service areas, and network hierarchy for operational planning.
  6. Private source, credentials, customer records, topology, OLT configuration, and internal deployment details remain outside the public portfolio repository.

Project guide

Explore the Noney Broadband NMS showcase

Run the public static gateway and documentation locally without requiring the retired production server or any private customer and infrastructure data.

For: Portfolio reviewers who want to inspect the public gateway, screenshots, and documentation without the retired production backend.

Prerequisites

  • A modern browser
  • Python 3 or another static HTTP server
  • The public showcase repository only; no private production credentials or customer data are required

Procedure

  1. Clone the public repository, which contains the static gateway, documentation, screenshots, messages, and demonstration assets—not the private production backend.
  2. Review README.md and docs/projectdoc.md for project context, system modules, deployment diagrams, operational boundaries, and status.
  3. Start a static server and open http://localhost:8000 to inspect the gateway experience.
  4. Treat redirect-config.json as demonstration configuration. Replace its example endpoints only in a controlled deployment and never commit private infrastructure addresses.
  5. Use the screenshots and NetVision demonstration to review the operational interface without reconnecting the retired production environment.
  6. Preserve the documented privacy boundary: do not add customer information, credentials, topology, OLT configuration, or private server code to the public repository.

Command reference

git clone https://github.com/Guang84/Noney-BSNL-Broadband-NMS.git
cd Noney-BSNL-Broadband-NMS
python3 -m http.server 8000

Verification

  • The public gateway, maintenance state, messages, and screenshots load locally
  • redirect-config.json contains demonstration-safe values only
  • Documentation consistently identifies the production server as retired

Troubleshooting & boundaries

  • A missing production endpoint is expected: the operational backend is intentionally retired and not part of the public showcase.
  • Do not add private tunnel URLs, customer records, OLT credentials, or internal topology to make the demo appear live.
  • Use the static documentation and screenshots as the authoritative portfolio view.

Testing

Noney Broadband NMS portfolio verification

Checks for the public gateway and documentary evidence of a completed, production-tested, now-retired operational platform.

  1. Serve the repository locally and verify the gateway, maintenance state, error page, icons, messages, and screenshots load without the production backend.
  2. Validate redirect-config.json syntax and ensure public builds contain only demonstration endpoints—not private tunnel, server, or infrastructure addresses.
  3. Review desktop and mobile presentation of the public landing page and each documented screenshot.
  4. Confirm the documentation consistently labels development completed, production tested, public gateway online, and the production server retired.
  5. Check that no customer records, credentials, internal topology, OLT configuration, private server code, or deployment secrets are present.
  6. Verify README.md and docs/projectdoc.md explain the static gateway, local production architecture, system modules, privacy boundary, and portfolio status.
