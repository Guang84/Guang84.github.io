Practical guide

Set up SSH Fleet Doctor safely

Prepare the Bash and Python tooling against a disposable or explicitly authorized SSH test host before considering operational use.

Related project: SSH Fleet Doctor — complete case study

For: Administrators or learners testing SSH monitoring against a disposable or explicitly authorized host.

Before you start

Prerequisites

  • Linux, macOS, or WSL
  • Python 3 and pip
  • An SSH client
  • A restricted account on a test host you are authorized to administer

Procedure

Step by step

  1. Use Linux, macOS, or WSL with Python 3, pip, an SSH client, and a test host you are authorized to administer.
  2. Clone the current SSH-Fleet-Doctor repository and inspect SETUP.sh, SSH_Infiltrator.sh, and python/SSH_Intruder.py before executing them.
  3. Run SETUP.sh to create the venv and install Paramiko, then activate the generated environment.
  4. Start the Python monitor with the test host IP and restricted username. Omit the password argument so the tool prompts instead of exposing it in shell history.
  5. Begin with read-only resource monitoring; review logs and remote permissions before enabling administrative operations.
  6. Prefer SSH keys, host-key verification, a restricted remote account, and tested backups for any non-disposable system.

Command reference

git clone https://github.com/Guang84/SSH-Fleet-Doctor.git
cd SSH-Fleet-Doctor
chmod +x SETUP.sh SSH_Infiltrator.sh
./SETUP.sh
source venv/bin/activate
python3 python/SSH_Intruder.py -i <authorized-host-ip> -u <restricted-user>

Verify

Confirm the result

  • The Python virtual environment activates and Paramiko imports successfully
  • Read-only CPU, memory, disk, and network checks work on the test host
  • Logs contain useful context without credentials or secrets

Troubleshooting

Common boundaries and failure checks

  • For connection failures, verify host reachability, SSH service status, username, and host-key expectations.
  • For dependency failures, recreate the virtual environment and install from the project setup script.
  • For production-like hosts, use SSH keys and a restricted account rather than command-line passwords.
